# Translate React emails with react-intl, react-i18next, or next-intl

Elements has no translation system of its own: use the i18n library your application already has. This guide renders one shipping notification in English and Arabic with [react-intl](#react-intl), [react-i18next](#react-i18next), and [next-intl](#next-intl). Every snippet is a file in the [i18n example](../../../examples/i18n), and its test renders both locales with each library.

```bash
pnpm install
pnpm build
pnpm --filter @unlayer/i18n-example test
pnpm --filter @unlayer/i18n-example render
```

`render` writes `examples/i18n/output/shipped.en.html` and `shipped.ar.html` (and the plain text of each). Open the Arabic file to see the right-to-left layout.

## The rules

1. **Load messages, then render.** `renderToHtml()`, `renderToPlainText()`, and `renderToJson()` are synchronous. Read message files, initialize the i18n instance, and fetch data before you call them. A template that suspends while its messages load (react-i18next's `useTranslation()` does) makes the renderer throw a `RenderError` naming it (`async and suspending templates need "@unlayer/react-elements/async"'s renderers, or their data loaded first`); a component further down that suspends or is `async` fails the render too, with a `RenderError` naming it (`it is async or suspends, and this renderer is synchronous`), unless you set `onError: "omit"`. Don't `await` translations inside a component. (The [async renderers](./async.md) render templates that load data, but messages loaded first keep the render synchronous, and the email can't go out with keys in it.)
2. **Providers and hooks work.** Wrap the template in the library's provider and call its hook in your components: Elements renders the template once, with React's hooks and context, so context reaches every component, including the one that returns `<Email>`. A provider written as a class component (react-intl's `<IntlProvider>`) works the same way: the root's `lang` and `textDirection` inside it are read.
3. **Give blocks strings or message components.** Call `intl.formatMessage()` or `t()` and pass the string to `Heading`, `Paragraph`, or `Button`, as the templates below do. Their children can also be `<FormattedMessage>` or `<Trans>`, which render with the template's context, formatting tags included. Props such as `previewText` and `href` take strings only.
4. **Set the language and direction on the root.** `<Email lang="ar" textDirection="rtl">` writes `<html lang="ar" dir="rtl">` and marks each text block `dir="rtl"`. The design JSON keeps `textDirection` but not `lang`; options passed to `renderToHtml()` override both props.
5. **Text follows the direction.** In a right-to-left email, `Heading` and `Paragraph` default to `textAlign="right"`, so Arabic or Hebrew text starts at the right edge. Pass `textAlign` to align a block otherwise. (Elements 0.2 left-aligned them in every direction.) With [Tailwind](./tailwind.md#right-to-left), logical classes follow the direction too: `ps-4` and `text-start` are the right side in a right-to-left email.
6. **Translate the subject and preview text too.** The subject goes to your email provider, not into the HTML; the inbox preview is the root's `previewText`.
7. **Escape once.** Elements escapes text passed as children, so turn off escaping in the i18n library (i18next's `escapeValue: false`) to avoid `&amp;lt;`. Values interpolated into a `Paragraph`'s `html` prop are raw markup: escape them yourself, as the [invoice template](./one-template-email-web-pdf.md#define-the-shared-react-template) does.

## Messages and direction

The example keeps one JSON file per locale in [messages/](../../../examples/i18n/messages), in ICU syntax, and all three libraries read the same files:

```json
{
  "shipped": {
    "subject": "تم شحن طلبك {orderId}",
    "preview": "طلبك في الطريق إليك.",
    "heading": "تم شحن طلبك",
    "greeting": "مرحبًا {name}، طلبك {orderId} في الطريق إليك.",
    "cta": "تتبّع شحنتك"
  }
}
```

[src/locales.ts](../../../examples/i18n/src/locales.ts) loads them and maps a locale to its direction:

```ts
import { readFile } from "node:fs/promises";

export const locales = ["en", "ar"] as const;
export type Locale = (typeof locales)[number];

/** One file per locale in messages/, nested by email, with ICU placeholders: "Hi {name}". */
export interface Messages {
  shipped: Record<"subject" | "preview" | "heading" | "greeting" | "cta", string>;
}

/** Elements renders synchronously, so load a locale's messages before rendering. */
export async function loadMessages(locale: Locale): Promise<Messages> {
  return JSON.parse(await readFile(new URL(`../messages/${locale}.json`, import.meta.url), "utf8"));
}

const RTL_LANGUAGES = new Set(["ar", "fa", "he", "ur"]);

/** The value for the root's `textDirection` prop. */
export function directionOf(locale: string): "ltr" | "rtl" {
  return RTL_LANGUAGES.has(new Intl.Locale(locale).language) ? "rtl" : "ltr";
}

export interface Order {
  id: string;
  customer: string;
  trackingUrl: string;
}

export const sampleOrder: Order = {
  id: "A-1042",
  customer: "Ada",
  trackingUrl: "https://example.com/orders/A-1042",
};
```

## react-intl

`createIntl()` makes the formatter for the subject, and `RawIntlProvider` gives the same one to the template, whose components call `useIntl()`. `<IntlProvider locale messages>` works as well. [src/react-intl.tsx](../../../examples/i18n/src/react-intl.tsx):

```tsx
import {
  Button, Column, ColumnLayouts, Email, Heading, Paragraph, Row,
  renderToHtml, renderToPlainText,
} from "@unlayer/react-elements";
import { createIntl, RawIntlProvider, useIntl } from "react-intl";
import { directionOf, type Locale, type Messages, type Order } from "./locales";

function ShippedEmail({ order }: { order: Order }) {
  const intl = useIntl();
  const values = { name: order.customer, orderId: order.id };
  const direction = directionOf(intl.locale);
  return (
    <Email
      lang={intl.locale}
      textDirection={direction}
      previewText={intl.formatMessage({ id: "shipped.preview" })}
    >
      <Row layout={ColumnLayouts.OneColumn} padding="24px">
        <Column>
          <Heading>{intl.formatMessage({ id: "shipped.heading" })}</Heading>
          <Paragraph>{intl.formatMessage({ id: "shipped.greeting" }, values)}</Paragraph>
          <Button href={order.trackingUrl}>{intl.formatMessage({ id: "shipped.cta" })}</Button>
        </Column>
      </Row>
    </Email>
  );
}

export function renderShippedEmail(locale: Locale, messages: Messages, order: Order) {
  // react-intl looks messages up by flat ids: { "shipped.heading": "…" }.
  const flat = Object.fromEntries(
    Object.entries(messages.shipped).map(([key, message]) => [`shipped.${key}`, message]),
  );
  const intl = createIntl({ locale, messages: flat });
  const email = (
    <RawIntlProvider value={intl}>
      <ShippedEmail order={order} />
    </RawIntlProvider>
  );
  return {
    subject: intl.formatMessage({ id: "shipped.subject" }, { orderId: order.id }),
    html: renderToHtml(email),
    text: renderToPlainText(email),
  };
}
```

## react-i18next

Create an i18next instance per locale and `await` its `init()`, so `useTranslation()` has its messages when the template renders. `i18n.dir()` gives the direction of the instance's language. [src/react-i18next.tsx](../../../examples/i18n/src/react-i18next.tsx):

```tsx
import {
  Button, Column, ColumnLayouts, Email, Heading, Paragraph, Row,
  renderToHtml, renderToPlainText,
} from "@unlayer/react-elements";
import i18next, { type i18n } from "i18next";
import { I18nextProvider, useTranslation } from "react-i18next";
import type { Locale, Messages, Order } from "./locales";

/** An i18next instance per locale, initialized before anything renders with it. */
export async function createI18n(locale: Locale, messages: Messages): Promise<i18n> {
  const instance = i18next.createInstance();
  await instance.init({
    lng: locale,
    resources: { [locale]: { translation: messages } },
    interpolation: {
      // The shared message files use {name}; i18next's default is {{name}}.
      prefix: "{",
      suffix: "}",
      // Elements escapes text children already.
      escapeValue: false,
    },
  });
  return instance;
}

function ShippedEmail({ order }: { order: Order }) {
  const { t, i18n } = useTranslation();
  const direction = i18n.dir();
  return (
    <Email lang={i18n.language} textDirection={direction} previewText={t("shipped.preview")}>
      <Row layout={ColumnLayouts.OneColumn} padding="24px">
        <Column>
          <Heading>{t("shipped.heading")}</Heading>
          <Paragraph>{t("shipped.greeting", { name: order.customer, orderId: order.id })}</Paragraph>
          <Button href={order.trackingUrl}>{t("shipped.cta")}</Button>
        </Column>
      </Row>
    </Email>
  );
}

export function renderShippedEmail(i18n: i18n, order: Order) {
  const email = (
    <I18nextProvider i18n={i18n}>
      <ShippedEmail order={order} />
    </I18nextProvider>
  );
  return {
    subject: i18n.t("shipped.subject", { orderId: order.id }),
    html: renderToHtml(email),
    text: renderToPlainText(email),
  };
}
```

Rendering with an instance that hasn't loaded its messages throws instead of sending keys or an empty email; the example's test checks this. Don't work around it with `useSuspense: false`: the template would render before the messages are there.

## next-intl

next-intl's request-scoped APIs need a Next.js request. Outside one (a script, a job worker, a test), use `createTranslator()`, which needs only a locale and messages. next-intl's Server Component entry exports it too, so the same template can run in a Route Handler. The translator is typed by the messages: a missing key is a type error. [src/next-intl.tsx](../../../examples/i18n/src/next-intl.tsx):

```tsx
import {
  Button, Column, ColumnLayouts, Email, Heading, Paragraph, Row,
  renderToHtml, renderToPlainText,
} from "@unlayer/react-elements";
import { createTranslator } from "next-intl";
import { directionOf, type Locale, type Messages, type Order } from "./locales";

type ShippedTranslator = ReturnType<typeof createTranslator<Messages, "shipped">>;

function shippedEmail(t: ShippedTranslator, locale: Locale, order: Order) {
  const direction = directionOf(locale);
  return (
    <Email lang={locale} textDirection={direction} previewText={t("preview")}>
      <Row layout={ColumnLayouts.OneColumn} padding="24px">
        <Column>
          <Heading>{t("heading")}</Heading>
          <Paragraph>{t("greeting", { name: order.customer, orderId: order.id })}</Paragraph>
          <Button href={order.trackingUrl}>{t("cta")}</Button>
        </Column>
      </Row>
    </Email>
  );
}

export function renderShippedEmail(locale: Locale, messages: Messages, order: Order) {
  // createTranslator needs no request: it works in scripts, job workers and Next.js server code alike.
  const t = createTranslator({ locale, messages, namespace: "shipped" });
  const email = shippedEmail(t, locale, order);
  return {
    subject: t("subject", { orderId: order.id }),
    html: renderToHtml(email),
    text: renderToPlainText(email),
  };
}
```

Inside a Next.js request (a Route Handler, a Server Action, or a Server Component), you can instead `await getTranslations({ locale, namespace: "shipped" })` from `next-intl/server`, with your next-intl request configuration, and pass the result to the template. Await it before rendering. Outside Next.js server code (in a plain Node.js script, for example) it throws an error saying `getTranslations` is not supported in Client Components. The example's test covers `createTranslator()` only. next-intl lists `next` as a peer dependency, so install it even where you only use `createTranslator()`.
